# ネットワーク部分のセキュリティ確認

ネット対戦 (`Assets/Scripts/Net`) と、それを使うゲーム側 (`GameDirector`, `NetworkMenuView`) を読み直した結果。
前提は「同じ LAN か、会場の閉域網 (他チームと共有) で、1 ポートだけ開けて使う」。
インターネットに直接さらす想定はしていない。

## 問題にならない点

- 受信データは自前の固定フォーマットを長さ検査付きで読むだけ (`ByteReader.Need`)。型の逆直列化、
  文字列の評価、ファイルやプロセスへのアクセスは一切しない。任意コード実行やメモリ破壊につながる経路は無い。
- 1 パケットの大きさは UDP のデータグラム上限 (64 KB)、TCP の 2 バイト長接頭辞 (64 KB) で抑えられ、
  配列の要素数は 1 バイト (最大 255) で読むので、巨大な割り当てを強いられない。
- クライアントが送れるのは「自分の機体の操作」「自分の同盟のスキル」だけで、ホストはスロットに紐付けて
  適用する。相手側の機体や試合の進行はホストしか変えられない (ホスト権威型)。
- 受信スレッドは例外を捕まえて続行し、主スレッドへはキュー経由で渡す。

## 直した点 (v0.3)

| リスク | 内容 | 対処 |
|---|---|---|
| 無認証の参加 | 誰でも部屋に入れる。共有ネットワークでは無関係な人が入り得る | 合言葉 (任意) を Hello に付け、違えば Reject。平文なので覗き見には効かないが誤入室・いたずらを防ぐ |
| 送信元の偽装 | UDP では送信元アドレスを偽ると他人の操作を注入できる | 参加時に 32 bit の乱数トークンを発行 (`RandomNumberGenerator`)。Input / Ping / Skill / Bye はトークンが合わなければ捨てる |
| TCP の接続攻撃 | 接続を張るだけで受信スレッドが増え、Hello を送らない接続が残る | 同時接続 16 まで。最初のフレームまで 15 秒、以後 30 秒の受信タイムアウトで閉じる |
| 反射・増幅 | Discover と不正な Hello に無条件で応答していた | 参加者以外への応答 (Announce / Reject) を毎秒 20 回まで。1 回の Pump で処理するパケットは 2000 まで |
| 例外の漏れ | 長さ不足以外の例外を捕まえていなかった | 受信処理全体で捕まえて捨てる |
| 表示の乗っ取り | 名前をそのまま uGUI に出すと `<size=200>` などのタグが解釈される | 名前はタグ・制御文字を落として 16 文字まで。UI の Text はリッチテキストを無効にした |
| スキル要求の滞留 | クライアントが Skill を大量に送るとキューが伸びる | キューは 64 件まで |

## 残っている前提と限界

- **暗号化していない。** 合言葉もトークンも平文で流れる。同じ LAN で盗聴できる相手には防げない。
  VPN (Secure Share Net のような閉域網) を通す運用なら、網側の暗号化に任せる形になる。
- **ホストは信頼する。** 細工したスナップショットをクライアントに送れば、見た目は好きに変えられる
  (クライアントは描画するだけで、物理も判定もホストにある)。
- **ホストは 0.0.0.0 で待ち受ける。** PC に複数のネットワークがある場合、全部から見える。会場では
  合言葉を付けること。インターネットに向けてポートを開放しないこと。
- UDP の Discover はブロードキャストなので、同じ LAN の全員に部屋の存在 (名前・人数) が見える。
- 名前やアドレスは `PlayerPrefs` に平文で保存する (合言葉も同様)。共用 PC では空にして終えること。
